# Real provider validation on 16 November 2026

Local environment: macOS arm64, AppleClang 21, Release and Debug builds; OpenSSL 3
from Homebrew. Source directories were prepared from the exact pinned release
revisions. The normal CI path additionally verifies source archive SHA-256 hashes.

Both release and AddressSanitizer/UndefinedBehaviorSanitizer builds passed all six
CTest groups. Sanitizers instrument the host, adapters and vendor static targets.
The real-provider matrix covers 26 mode/encryption/address/provider combinations
per load order (52 across both orders), plus simultaneous encrypted transfers,
independent shutdown, wrong-passphrase rejection, stale/cross-provider handles,
short-buffer preservation and optional accounting. Export allowlists pass for the
actual modules, not only fixtures. Linux/macOS CI results are tracked separately
in the repository's workflow; Windows real-provider qualification is still pending.

## Exploratory throughput samples

[Raw samples and build fingerprints](2026-11-16-file-loopback.json), captured on
commit `72ed86d` before the subsequent teardown-only correction, contain three
interleaved runs per provider/path. Each run warms up with 8 MiB and verifies a
128 MiB File/IPv4 plaintext transfer with 32 KiB calls. The direct and module paths
link the same vendor static targets and use matching options. No compilation or
other task-owned benchmark ran concurrently with the recorded samples.

| Provider | Median module throughput change vs direct | Median CPU seconds per byte change |
| --- | --- | --- |
| Robotweax 0.3.3 | -0.96% | +1.10% |
| Haivision 1.5.7 | +21.32% | -13.16% |

These are observations, not a claim of speedup or release qualification. Haivision
samples have substantial variance, so the positive median cannot establish an
adapter advantage. Three short shared-host trials, without affinity, latency
measurement or confidence bounds, cannot prove the proposed throughput/CPU budgets.
No data corruption or missing delivered bytes was accepted to improve a result.

## Native File and IPv6 limitation

A separate executable linked directly to the same Haivision 1.5.7 static library
reproduced setup success followed by 32,768 bytes accepted and zero bytes received
on IPv6 loopback. There is no provider-host or adapter code in that executable.
The module matrix also reproduced the failure at 336,896 bytes in both load orders.
The basic adapter explicitly rejects Haivision File/IPv6 pending qualification;
it introduces no packet-size workaround or silent provider fallback.
